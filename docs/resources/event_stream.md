# ory_event_stream (Resource)

Manages an Ory Network event stream.

Event streams publish Ory events, such as identity creation and session creation, to an AWS SNS topic or to an HTTPS endpoint. See [Live Event Streams](https://www.ory.com/docs/actions/live-events) for full setup instructions.

-> **Plan:** Requires an Ory Network **Enterprise plan**.

~> **Authentication:** Event streams are managed via the Console API and require a `workspace_api_key` to be configured in the provider. A `project_api_key` alone is not sufficient.

## AWS SNS Setup

To stream events to AWS SNS, you need:

1. **An SNS topic** in your AWS account
2. **An IAM role** with `sns:Publish` permission on the topic
3. **A trust policy** on the role allowing Ory's AWS account (`601538168777`) to assume it, with your Ory project UUID as the `sts:ExternalId`

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {
        "AWS": "arn:aws:iam::601538168777:root"
      },
      "Action": "sts:AssumeRole",
      "Condition": {
        "StringEquals": {
          "sts:ExternalId": "<your-ory-project-uuid>"
        }
      }
    }
  ]
}
```

See the [Ory documentation](https://www.ory.com/docs/actions/live-events#stream-to-aws-sns) for complete setup instructions.

## HTTPS Endpoint Setup

To stream events to an HTTPS endpoint, set `type = "https"` and `https_endpoint`. The endpoint must:

1. Use HTTPS. Ory does not send events to unencrypted HTTP endpoints.
2. Accept a `POST` request with a JSON body, and answer with a 2xx status after it processes the event. Ory does not follow redirects.

Ory recommends HTTP/2 for the endpoint, so that Ory can send several events over one connection. See the [Ory documentation](https://www.ory.com/docs/actions/live-events#stream-to-https-endpoint) for the event format.

When Terraform creates or updates an active stream, Ory sends a test event to the endpoint. If the endpoint does not answer with a 2xx status, the apply fails. To create the stream before the endpoint is ready, set `status = "paused"`.

Deliveries can authenticate in three ways:

| Method | Configuration |
|---|---|
| Basic | Put the credentials in the userinfo of `https_endpoint`, for example `https://user:secret@events.example.com/ory`. |
| API key | Set `https_auth_type = "api_key"`, `https_auth_header_name`, and `https_auth_secret`. |
| Bearer token | Set `https_auth_type = "bearer"` and `https_auth_secret`. Ory sends `Authorization: Bearer <secret>`. |

Credentials in the endpoint URL cannot be combined with a bearer token, or with an API key in the `Authorization` header, because both set the `Authorization` header. With Terraform 1.11 and later, use `https_auth_secret_wo` to keep the secret out of the Terraform state.

## Example Usage

```terraform
# Publish Ory events to an AWS SNS topic
resource "ory_event_stream" "events" {
  type      = "sns"
  topic_arn = "arn:aws:sns:us-east-1:123456789012:ory-events"
  role_arn  = "arn:aws:iam::123456789012:role/ory-event-publisher"
}

# Send Ory events to an HTTPS endpoint, authenticated with a bearer token
variable "event_stream_token" {
  type      = string
  sensitive = true
}

resource "ory_event_stream" "webhook" {
  type              = "https"
  https_endpoint    = "https://events.example.com/ory"
  https_auth_type   = "bearer"
  https_auth_secret = var.event_stream_token
}

# Send Ory events with an API key header, and keep the stream paused
resource "ory_event_stream" "paused" {
  type                   = "https"
  https_endpoint         = "https://events.example.com/ory-staging"
  https_auth_type        = "api_key"
  https_auth_header_name = "X-Api-Key"
  https_auth_secret      = var.event_stream_token
  status                 = "paused"
}

output "event_stream_id" {
  value = ory_event_stream.events.id
}
```

## Import

Event streams can be imported using the event stream ID (uses the provider's `project_id`):

```shell
terraform import ory_event_stream.example <event-stream-id>
```

Or with an explicit project ID:

```shell
terraform import ory_event_stream.example <project-id>/<event-stream-id>
```

-> **Note:** The API never returns `https_auth_secret`, and it returns the userinfo and the query values of `https_endpoint` as `xxxxx`. After an import, set both values in the configuration. The first apply then sends them to Ory.

## Schema

### Required

- `type` (String) The type of the event stream: "sns" publishes events to an AWS SNS topic, and "https" sends each event to an HTTPS endpoint in a POST request. Changing the type updates the stream in place.

### Optional

> **NOTE**: [Write-only arguments](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments) are supported in Terraform 1.11 and later.

- `https_auth_header_name` (String) The header that carries the API key. Required when https_auth_type is "api_key", and not valid with any other scheme. Ory rejects a header it sets itself, such as Content-Type or User-Agent, and a name that starts with Ory- or X-Ory-.
- `https_auth_secret` (String, Sensitive) The API key or bearer token, at most 4096 bytes. Stored in Terraform state. The API never returns it, so a change made outside Terraform is not detected. Changing the value rotates the secret. When https_auth_type is "api_key" or "bearer", exactly one of https_auth_secret and https_auth_secret_wo must be set.
- `https_auth_secret_wo` (String, Sensitive, [Write-only](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments)) Write-only equivalent of https_auth_secret for Terraform 1.11 and later: the value is sent to Ory but never stored in Terraform state or plan. Use it to source the secret from an ephemeral resource such as a Vault secret. Because write-only values are not persisted, Terraform cannot detect when the value changes on its own. Change https_auth_secret_wo_version to rotate it. Mutually exclusive with https_auth_secret.
- `https_auth_secret_wo_version` (String) Version trigger for https_auth_secret_wo. Change this value whenever the write-only secret changes so Terraform sends the new value to Ory. Has no effect unless https_auth_secret_wo is set.
- `https_auth_type` (String) How deliveries to the HTTPS endpoint authenticate: "none", "api_key" to send the secret in the header named by https_auth_header_name, or "bearer" to send it in the Authorization header as a bearer token. Only "none" is valid when type is "sns". Defaults to "none".
- `https_endpoint` (String, Sensitive) The HTTPS URL that receives the events. Required when type is "https". Ory sends the credentials in the userinfo of the URL as Basic authentication. The API masks the userinfo and every query value on read, so Terraform keeps the configured URL and compares the masked forms to detect a change made outside Terraform.
- `project_id` (String) The project ID. If not set, uses the provider's project_id.
- `role_arn` (String) The AWS IAM role ARN to assume when publishing to the SNS topic. Required when type is "sns".
- `status` (String) The status of the event stream: "active" or "paused". A paused stream does not forward events, and Ory holds them for up to seven days until the stream is active again. Ory tests the destination on every create and update of an active stream, and skips the test for a paused stream. Defaults to "active".
- `topic_arn` (String) The AWS SNS topic ARN to publish events to. Required when type is "sns".

### Read-Only

- `created_at` (String) Timestamp when the event stream was created.
- `id` (String) The unique identifier of the event stream.
- `updated_at` (String) Timestamp when the event stream was last updated.
