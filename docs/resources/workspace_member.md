# ory_workspace_member (Resource)

Gives one person access to an Ory Network workspace through an invite.

Ory emails the invite to `email`. The person accepts the invite with a Console account that uses the same address, and then has the configured `role` on the workspace and on every project in it. `status` is `pending` until the person accepts the invite, and `accepted` after. See [Roles and permissions](https://www.ory.com/docs/console/roles-and-permissions) for what each role can do. To give access to one project only, use `ory_project_member`.

-> **Plan:** Available on all Ory Network plans. Members and pending invites count as collaborator seats, so the seat limit of the plan applies.

~> **Authentication:** The Ory Console API accepts member and invite requests only from a signed-in Console user, and answers a workspace API key with HTTP 401. Run `ory auth` and set `workspace_api_key` to the access token, as [Managing a project without a workspace API key](https://registry.terraform.io/providers/ory/ory/latest/docs#managing-a-project-without-a-workspace-api-key) describes. The user must be an owner of the workspace.

## Example Usage

```terraform
# Invite a person to the workspace from the provider configuration.
resource "ory_workspace_member" "carol" {
  email = "carol@example.com"
  role  = "developer"
}

# Invite a workspace owner.
resource "ory_workspace_member" "dave" {
  email = "dave@example.com"
  role  = "owner"
}
```

## Important Behaviors

- **A role change replaces the member.** The API cannot change the role of a member. A new `role` removes the person from the workspace and sends a new invite, which the person must accept again.
- **One invite per person.** Create fails when the person already has access to the workspace or a pending invite to it. Import the person instead.
- **A closed invite leaves the state.** The person can decline the invite, the invite can expire, and someone can cancel the invite or remove the member in the Console. After each of these, the next plan shows the member as new, and the next apply sends a new invite.
- **Destroy revokes access.** Destroy cancels a pending invite. After the person accepts, destroy removes the person from the workspace.
- **A member without an invite is read from the members list.** Some members have no invite, such as the person who created the workspace. The resource reads their role from the members list, and `invite_id` is null.
- **`email` must be lowercase.** Ory stores invitee emails in lowercase.
- **The API refuses to remove the signed-in user.** Do not manage the person whose token Terraform uses.

## Import

Import a member or a pending invite with the workspace ID and the email address. Without a workspace ID, the provider's `workspace_id` is used:

```shell
terraform import ory_workspace_member.carol <workspace-id>/carol@example.com
terraform import ory_workspace_member.carol carol@example.com
```

## Schema

### Required

- `email` (String) The email address of the person, in lowercase. Ory sends the invite to this address. The person must accept it with a Console account that uses the same address.
- `role` (String) The role of the person. One of `owner`, `developer`, `viewer`. A change removes the person and sends a new invite, because the API cannot change the role of a member.

### Optional

- `workspace_id` (String) The workspace ID. If not set, the provider's `workspace_id` is used.

### Read-Only

- `id` (String) The resource ID, `<workspace_id>/<email>`.
- `invite_id` (String) The ID of the invite. Null for a member who joined without an invite.
- `member_id` (String) The Ory Network user ID of the person. Ory sets it when the person links the invite to their Console account, at the latest when they accept the invite.
- `status` (String) `pending` until the person accepts the invite, then `accepted`.
